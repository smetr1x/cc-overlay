# ADR-0010. Лимиты подписки через команду `/usage`

Статус: принято (2026-11-16). Дополняет [ADR-0009](0009-statusline-bridge.md).

## Контекст

Мост из status line даёт точный процент лимита, но status line запускается только в терминальном Claude Code. Владелец работает в основном в расширении VS Code, и там лимиты не обновлялись. Требовался источник, не зависящий от способа запуска.

Рассмотренный вопрос: можно ли изменить расширение, чтобы оно вызывало status line. Расширение — закрытый минифицированный пакет, который перезаписывается при каждом обновлении. Правка его кода держалась бы до ближайшего обновления и не опирается ни на один документированный интерфейс.

## Решение

Лимиты берутся из ответа Claude Code на команду `/usage` в неинтерактивном режиме:

```bash
claude -p "/usage" --output-format stream-json --verbose --no-session-persistence
```

В ответе есть сообщение с полем `usage_report.rate_limits.limits` — те же строки, что показывает диалог Usage. Тип `SDKUsageReport` описан в справочнике Agent SDK.

Вызов делает хук Claude Code `hooks/cc-overlay-usage.sh`, подключённый к событиям `SessionStart`, `PostToolBatch` и `Stop` с `"async": true`. Хуки срабатывают и в терминале, и в расширении. Скрипт отправляет блок лимитов в `POST /api/v1/usage`; overlay-api раскладывает строки по полю `kind`:

| `kind` | Куда попадает |
|---|---|
| `session` | `limits.five_hour` |
| `weekly_all` | `limits.seven_day` |
| `weekly_scoped` | `limits.scoped[]` с названием модели или поверхности |
| прочие | пропускаются |

## Что проверено на машине владельца

Claude Code 2.1.312, тариф Pro:

- ответ содержит три строки: `session`, `weekly_all` и `weekly_scoped` для модели Fable;
- запрос к модели не выполняется: `num_turns: 0`, `total_cost_usd: 0`, все счётчики токенов нулевые, модель в ответе `<synthetic>`;
- вызов занимает около 0,7 секунды;
- со вложенными настройками `CLAUDE_CODE_ENABLE_TELEMETRY=0` в Prometheus не появляется новая сессия; без них каждая проверка создавала бы серию `claude_code_session_count_total`.

## Альтернативы

**Правка расширения.** Отклонена, см. выше.

**Терминальный режим расширения** (`claudeCode.useTerminal`). Документированная настройка: Claude открывается в VS Code как терминал, и status line работает. Цена — потеря графической панели. Остаётся доступным, решение его не исключает.

**Обёртка процесса** (`claudeCode.claudeProcessWrapper`) с разбором потока сообщений. Настройка документирована, но обёртка встала бы на пути всего обмена между расширением и Claude: её ошибка ломала бы рабочий инструмент. Кроме того, событие `rate_limit_event` в потоке не содержит процента по окнам.

**Оценка процента по расходу из метрик с калибровкой.** Не нужна: есть точное значение.

**Фоновый опрос по таймеру** (cron, systemd). Работал бы и тогда, когда Claude Code не используется. Хук запускается ровно тогда, когда лимит меняется, и не требует отдельного процесса.

**Недокументированный HTTP-адрес, которым пользуется диалог Usage.** Потребовал бы читать учётные данные из файлов Claude Code; не рассматривался.

## Почему так

Принцип тот же, что в ADR-0009: измеренное значение лучше вычисленного. Процент считает сервер, а `/usage` — штатный способ его получить. Хук — штатная точка расширения, которая одинаково работает во всех оболочках Claude Code.

## Последствия

- Нужна правка `~/.claude/settings.json` (ключ `hooks`); её делает владелец.
- Скрипт ничего не печатает и запускается асинхронно: в контекст модели ничего не попадает, работа не задерживается.
- Между опросами не меньше 60 секунд (`CC_OVERLAY_USAGE_INTERVAL`): событий много, лимит меняется медленно. Внутри длинного хода значение обновляется по `PostToolBatch`.
- Защита от рекурсии: вложенный `claude -p` запускается с `disableAllHooks` и переменной `CC_OVERLAY_NESTED`, по которой скрипт сразу выходит.
- Вложенный запуск идёт из временного каталога и с `--no-session-persistence`: в истории сессий проекта он не появляется.
- Тип `SDKUsageReport` помечен в документации как экспериментальный. Неизвестные значения `kind` пропускаются; если поле исчезнет, скрипт запишет это в `/tmp/cc-overlay-usage.last`, а лимиты в оверлее пометятся устаревшими.
- Поле `usage_report` есть только при входе через подписку claude.ai.
- Status line остаётся: в терминале он даёт точное заполнение контекста. Лимиты берутся из того источника, чей отчёт пришёл последним; поле `limits.source` показывает, из какого.
