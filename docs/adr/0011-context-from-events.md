# ADR-0011. Заполнение контекста из событий, через метрику в коллекторе

Статус: принято (2026-11-16). Меняет план: оценка контекста перенесена из фазы 4 и больше не зависит от Loki.

## Контекст

Точное заполнение контекста даёт status line, но в расширении VS Code он не запускается ([ADR-0009](0009-statusline-bridge.md)). Для таких сессий остаётся телеметрия: событие `claude_code.api_request` несёт число входных токенов запроса.

По плану фазы 0 событие читалось бы из Loki. Тогда ради одного числа в оверлее Loki должен работать постоянно, а бюджет памяти этого не позволяет ([architecture.md](../architecture.md)).

## Решение

Коллектор превращает событие в метрику коннектором `signal_to_metrics`:

- условие: `event.name` равен `api_request` и `query_source` равен `main`;
- значение: `input_tokens + cache_read_tokens + cache_creation_tokens`;
- метрика: gauge `claude_code.context.tokens` с меткой `session_id`, в Prometheus — `claude_code_context_tokens`.

Дальше метрика идёт существующим путём. overlay-api делит её на размер окна контекста и отдаёт в `session.context` с `source: "telemetry"` и `approximate: true`.

События нигде не сохраняются: конвейер логов заканчивается коннектором.

## Почему эта формула

Входные токены запроса — это всё, что модель получила на вход, то есть занятая часть окна. Документация status line считает `used_percentage` так же: `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`, без выходных токенов.

Учитываются только запросы основного диалога. Вспомогательные запросы и субагенты имеют собственный контекст, и их числа исказили бы оценку.

После сжатия контекста отдельная обработка не нужна: следующий запрос приходит с меньшим числом токенов, и метрика падает сама.

## Почему это оценка

- **Размер окна в телеметрии не передаётся.** Он берётся из `overlay-api/config.yaml`: 200 000 по умолчанию и исключения по модели. При окне в миллион токенов без записи в конфиге процент будет завышен впятеро.
- **Выходные токены последнего ответа** войдут в контекст следующего запроса, но в текущее значение не входят.
- **Между запросами значение не меняется.**

Если для сессии есть свежий отчёт status line, используется он, а размер окна из него применяется и к оценке.

## Альтернативы

**Loki и LogQL.** Отклонено из-за памяти, см. контекст. Loki остаётся в плане фазы 4 для истории и латентности.

**Хук `Stop`, читающий файл транскрипта.** Хуки получают `transcript_path`, а в транскрипте есть счётчики токенов. Формат файла не документирован.

**Приём OTLP прямо в overlay-api.** Потребовал бы реализовать в сервисе приёмник OTLP; коллектор уже умеет всё нужное.

## Последствия

- В настройках Claude Code нужно включить экспорт событий: `OTEL_LOGS_EXPORTER=otlp`.
- Коннектор в статусе alpha. В отличие от `deltatocumulative`, состояния он не хранит: рестарт коллектора ничего не ломает, значение восстановится со следующим запросом.
- После завершения сессии метрика остаётся в экспортёре на `metric_expiration` (15 минут) и затем исчезает.
- Проверено на синтетике: число и строка в атрибутах токенов обрабатываются одинаково. Форма событий настоящего Claude Code (имя события, наличие `query_source`, типы атрибутов) проверяется после включения экспорта; условие учитывает оба варианта имени события.
- Конвейер логов удаляет те же идентификаторы пользователя, что и конвейер метрик, а также атрибуты с содержимым промптов и аргументов инструментов.
