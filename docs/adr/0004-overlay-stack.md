# ADR-0004. Оверлей на Tauri 2

Статус: принято (2026-11-16). Подтверждает решение по умолчанию из ТЗ с двумя оговорками.

## Контекст

Нужно окно Windows: поверх всех окон, без рамки, полупрозрачное, пропускающее клики, с глобальным хоткеем «режим перемещения» и сохранением позиции. Данные приходят по SSE с `127.0.0.1`.

## Решение

Tauri 2. Фронтенд — TypeScript и Vite без UI-фреймворка. Окно создаётся с `transparent`, `decorations: false`, `alwaysOnTop`, `skipTaskbar`. Пропуск кликов включается вызовом `setIgnoreCursorEvents(true)`, хоткей временно его снимает. Используются плагины `global-shortcut` и `window-state`.

## Альтернативы

| Вариант | Память | Почему не выбран |
|---|---|---|
| Electron | 200+ МБ | несёт собственный Chromium; в разы тяжелее при тех же возможностях |
| PySide6 | 80–120 МБ | требует Python на Windows и отдельной упаковки; прозрачность и пропуск кликов делаются через WinAPI вручную |
| Нативный Rust (egui, Win32) | 15–30 МБ | самый лёгкий, но вёрстка и анимации заметно дороже в разработке |
| Rainmeter | 20–40 МБ | сборка не нужна, но ограниченный язык скинов, нет SSE, только опрос |
| Grafana kiosk + PowerToys | 300+ МБ | это вкладка браузера: нет пропуска кликов и нормальной прозрачности |

## Почему так

Tauri использует системный WebView2, поэтому дистрибутив занимает несколько мегабайт. Интерфейс пишется обычными веб-средствами, а нужные свойства окна доступны через API без обращения к WinAPI.

## Оговорки к ТЗ

**«Прозрачность и click-through из коробки» — верно наполовину.** Пропуск кликов включается на всё окно целиком. Сделать кликабельной отдельную кнопку внутри прозрачного окна штатными средствами нельзя. Отсюда и хоткей режима перемещения: он переключает всё окно.

**Цель «до 100 МБ» с WebView2 под вопросом.** Процессы WebView2 обычно занимают 80–150 МБ суммарно. Цель смягчена до ≈150 МБ; фактическое значение измеряется в фазе 3. Если это окажется неприемлемо, запасной вариант — нативный Rust-интерфейс, его контракт с overlay-api тот же.

## Дополнение по итогам фазы 3 (2026-11-17)

Замеры на машине владельца, Windows 11, окно с настоящими данными:

| Показатель | Значение |
|---|---|
| Размер `cc-overlay.exe` | 3,2 МБ |
| Память, сумма частной памяти процесса и шести процессов WebView2 | 187 МБ с GPU, **101 МБ** с `--disable-gpu` |
| Из них сам `cc-overlay.exe` | 7 МБ |
| Процессор в простое, обновление раз в секунду | около 2 % одного ядра |
| Первая сборка / пересборка | 4 минуты / 3 минуты |

**WebView2 запускается с `--disable-gpu`.** Из 187 МБ 94 приходилось на GPU-процесс. Для десятка строк текста аппаратное ускорение не нужно; прозрачность окна без GPU сохраняется — проверено снимком области экрана. Флаг задан в `additionalBrowserArgs` вместе со значениями Tauri по умолчанию, которые иначе были бы потеряны.

Цель ТЗ в 100 МБ почти достигнута, смягчённая цель в 150 МБ выполнена.

**Окно подгоняется под панель.** Размер окна меняется вслед за содержимым (`ResizeObserver` → `setSize`). Иначе фиксированное окно обрезало строки справа, а в режиме перемещения рамка охватывала пустое место.

**Хоткеи.** Все на `Ctrl+Alt`: `M` — перемещение, `C` — компактный режим, `↑`/`↓` — прозрачность, `H` — спрятать, `Q` — выйти. Сочетание занято другой программой — оверлей всё равно запускается, без этого хоткея.

Проверено автоматически: окно поверх всех (`WS_EX_TOPMOST`), пропускает клики (`WS_EX_TRANSPARENT`); `Ctrl+Alt+M` снимает пропуск кликов, повторное нажатие возвращает его и записывает позицию в `%APPDATA%\local.cc-overlay\.window-state.json`.

## Последствия

- Сборка только на стороне Windows с тулчейном MSVC ([windows-toolchain.md](../windows-toolchain.md)). Из WSL оверлей не собирается.
- Страница оверлея обращается к `http://127.0.0.1:8787` с origin приложения Tauri. overlay-api обязан отдавать CORS-заголовки для этого origin, и только для него ([ADR-0006](0006-transport-sse.md)).
- Окно не отображается поверх игр в эксклюзивном полноэкранном режиме. Afterburner решает это внедрением в графический конвейер; для рабочего стола и оконных приложений это не требуется.
- В CI оверлей собирается отдельной задачей на Windows-раннере; она добавляется в фазе 3.
