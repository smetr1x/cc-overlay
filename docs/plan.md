# План фаз 1–5

Оценка сложности: S — до одного вечера, M — два-три вечера, L — неделя вечеров. После каждой фазы — коммит, отчёт и остановка до подтверждения.

## Фаза 1. Пайплайн метрик — M (выполнена)

Состав:

- `compose.yaml`: коллектор, Prometheus, Grafana (профиль `history`); версии закреплены, порты на `127.0.0.1`, у каждого сервиса `mem_limit` и healthcheck.
- `collector/config.yaml`, `prometheus/prometheus.yml`, provisioning источника данных Grafana.
- `tools/synth` на Go: две параллельные сессии, режимы cumulative и delta, все пять идентификаторов в атрибутах.
- `Makefile`: `up`, `down`, `logs`, `check`, `test`, `test-e2e`. Линтеры и валидаторы запускаются из закреплённых образов.
- `.env.example`, `README.md` с блоком `env`, `.github/workflows/ci.yaml`.

Эксперименты, результаты которых записываются в `telemetry-verification.md`:

1. Cumulative-экспорт работает, неизменившиеся серии переэкспортируются.
2. Поведение `session.id` и счётчиков при `--resume`.
3. Фактические имена метрик и меток.
4. Проброс `127.0.0.1` из WSL в Windows.

Главный риск: эксперимент 1. При отрицательном результате пересматривается ADR-0001.

Требует согласия владельца: правка `~/.claude/settings.json` (агент показывает diff).

## Фаза 2. overlay-api — M–L (выполнена)

Состав:

- Конфиг из окружения и файла: адреса, интервалы, пороги цветов, часовой пояс, размеры окна контекста по моделям, список origin для CORS.
- Шаблон «итог за окно», страж сбросов, выбор текущей сессии, автомат статусов.
- `/api/v1/snapshot`, `/api/v1/stream`, `/api/v1/statusline`, `/healthz`, `/metrics`.
- Скрипт status line.
- Unit-тесты с фейковым Prometheus, e2e на синтетике по семи сценариям из `queries.md`.

Главный риск: корректность шаблона на границах окна и автомата статусов.

## Фаза 3. Оверлей — L (в работе)

Разбита на две части, потому что на Windows ещё нет Rust и MSVC.

- **3а, выполнена:** интерфейс на TypeScript и Vite без фреймворка. Модель отображения — чистая функция от снимка (`overlay/src/view.ts`), покрыта тестами на все состояния. Открывается в браузере командой `make overlay-dev`; запросы к overlay-api идут через прокси Vite, поэтому CORS для разработки не нужен.
- **3б, ждёт тулчейна:** оболочка Tauri — окно поверх всех окон, прозрачность, пропуск кликов, хоткей перемещения, сохранение позиции.

Состав:

- Проект Tauri 2 в `overlay/`: окно, пропуск кликов, хоткей перемещения, сохранение позиции и прозрачности, компактный и развёрнутый режимы.
- Показатели MVP и показатели status line, все состояния из `architecture.md`.
- Инструкция по сборке на Windows, задача CI на Windows-раннере.
- Измерение задержки и памяти.

Главные риски: установка тулчейна, сборка из пути с кириллицей, память WebView2, проброс портов.

## Фаза 4. События и история — M

Состав:

Главный риск: бюджет памяти.

## Порядок и зависимости

Фазы идут строго по порядку. Фаза 3 зависит от контракта снимка из фазы 2; чтобы не блокироваться тулчейном, его можно установить на Windows заранее, во время фаз 1–2.
